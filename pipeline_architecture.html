🔬 How the Deterministic Engine Identifies Happy, Error & Boundary Paths
🟢
Happy Path Identification
Identified by tracing the CFG path from program ENTRY to the SUCCESS_SINK paragraph, conjoining all gatekeeper predicates into a single satisfiable formula.
Φ_Happy = ⋀ P_i(X) ∧ (SQLCODE == 0) ∧ (FILE_STATUS == "00")
  • 1 AST Sink Classification: Labels normal exit & approval nodes as target terminal.
  • 2 Conjunction of True Branches: Traverses all IF / EVALUATE blocks taking True branch.
  • 3 Central Nominal Value: Z3 solves for interior numbers within valid ranges.
🔴
Error Path Identification
Identified by systematically applying Weakest Precondition Inversion (negating each branch gatekeeper individually) and injecting external dependency failure codes.
Φ_Error_k = (⋀_{i < k} P_i) ∧ ¬P_k ∨ (SQLCODE == 100)
  • 1 Branch Inversion: Negates branch condition k while keeping prior steps valid.
  • 2 AST Error Sinks: Targets nodes with ROLLBACK, ABEND, or error return codes.
  • 3 Dependency Fault Injection: Solves for DB2 +100/-911 and VSAM '23' not-found states.
🟡
Boundary Identification
Identified by analyzing relational AST comparison operators (>=, <=, <, >) and calculating the 4 deterministic edge points around every limit.
Points = { Limit, Limit - ε, Limit + ε, Min(PIC), Max(PIC) }
  • 1 Operator Parsing: Extracts threshold literal L from IF X >= L.
  • 2 Discrete Step Calculation: Generates $X = L$, $X = L-1$, and $X = L+1$.
  • 3 Type Physical Extremes: PIC 9(6) bounds (000000 to 999999, HIGH/LOW-VALUES).
🔗 How External Dependency Mocks are Generated via Symbolic Execution
1
Treat Dependency Outputs as Free Symbolic Variables

When the AST encounters an EXEC SQL SELECT or READ VSAM, the output columns (e.g. CREDIT_SCORE) and status codes (SQLCODE) are treated as unknown symbolic inputs in Z3, rather than static constants.

2
Bind Primary Input Keys to Query Predicates

The WHERE clause key (e.g. WHERE CUST_ID = :IN-CUSTOMER-ID) is bound via equality constraints: MOCK_DB_KEY == IN_CUSTOMER_ID.

3
Single Co-Solved SMT Equation System

Z3 solves primary inputs and mock return values simultaneously in one pass, ensuring mathematical harmony between what the program passes in and what the mock returns.

4
AST-Driven Split into Primary vs Mock Artifacts

The unified solver model is split into 01_happy_path.json (inputs) and mocks/sql_mock_data.json (mock DB rows with exact matching keys).

01. Business Rule Extraction (BRD) HYBRID (AST + AI)

Why this approach? AST parser extracts precise paragraph lines & branch boundaries deterministically; LLM translates raw COBOL logic & comments into human-readable business rules.

Scans the workspace metadata to extract all decision points, EVALUATE blocks, and Level-88 conditions into business rules. The developer selects a specific rule to target rather than testing the entire monolith at once.

  • Interactive selection of target rule (e.g. BR-04 Tiered Risk Assessment)
  • Direct mapping from business criteria to COBOL Paragraph AST nodes
  • Eliminates whole-program path explosion by focusing the SMT solver
